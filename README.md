## 現場量測程序（0.5）

1. 用捲尺量一次鏡頭離地高度並輸入；App 會記在這支手機，換人再重量。
2. 樹高：站在與樹基等高的平地、離樹約 8–12 m。準星對準樹基（畫面即時顯示距離）→ 記錄；腳不動，往上對準樹頂（畫面即時顯示樹高）→ 記錄。按鈕或點相機畫面都能記錄，需穩住約半秒。
3. 冠幅：東西向站在樹的正南或正北方，南北向站在正東或正西方。先對準樹幹基部取得距離，再原地水平轉動手機，分別對準樹冠左右兩側最外緣。
4. 到樹旁取得定位，填周長及基本資料，保存紀錄並匯出。
5. 角度不需校正；若比對已知高度發現固定偏差，可在量測畫面用「校正一次（選用）」，校正值存在該手機。

### 量測假設與限制

- 距離 `D = h / tan(-β)`，樹高 `H = D × (tan α − tan β)`；h 為鏡頭離地高度，β 為樹基俯角（負值），α 為樹頂仰角。
- 冠幅 `W = D × (tan|θ₁| + tan|θ₂|)`，θ 為從樹幹方向起算的水平轉角，兩端須在樹幹左右兩側，各限 1°–70°。假設兩端與樹幹大致位於垂直視線的同一條線上；樹冠偏斜時誤差變大。
- 轉角取自手機姿態的相對方位（陀螺儀融合），只在同一次量測內相減，不依賴羅盤絕對方位；感測器來源若中途改變會要求重量。
- 必須地面等高；樹高模式假設最高點大致在樹基正上方。斜坡、傾斜樹與錯誤頂點都可能造成明顯誤差。
- 俯角限 5°–75°，樹頂仰角限 0°–60°。站太遠時俯角很小，例如 h=1.5 m、D=15 m 時角度差 1° 約造成 17% 距離誤差，因此建議 8–12 m；樹基俯角小於 8° 時結果會提示。
- 進階選項仍可改用捲尺實量水平距離，或輸入外部工具讀角。
- 所有此法尺寸均標記為估測。尚未驗證實體 iPhone / Android 的相機、姿態軸及校園精度。

## 手機現場驗證清單

先各用一支 iPhone 與 Android 測試，勿直接用於正式成果：

1. HTTPS 上的相機、感測器、定位允許／拒絕流程。
2. 鏡頭水平時約 0°，往上為正、往下為負；換方向仍一致。
3. 選已知高度的標記，以及捲尺量好的 3 m、5 m、8 m 地面端點，每點各測三次。
4. 選 5–10 株不同樹形，用捲尺基線＋工具讀角作為樹高對照，兩方向複測。
5. 比較兩向冠幅與捲尺，記錄絕對誤差、相對誤差、機型與地面條件。
6. 實際保存一筆、重新開啟、下載 Excel、在 Excel 中改周長，確認公式重算。

## 0.3 樹高逐步量測（2026-10-05）

樹高改成五步驟：填距離／鏡頭高度 → 啟用與水平校正 → 樹基 → 樹頂 → 結果。預設捲尺實量水平距離；每一步只顯示目前需要的控制項，校正及記錄成功後自動前往下一步。可回上一步或重新量測，後續暫存數據會同步失效；重新開啟樹高時清空距離與鏡頭高度，避免沿用上一站數值。手動工具角度收在進階選項，不用於取代真實手機現場驗證。既有冠幅與 Excel 碳公式保留。已加入流程防跳步、回退、重開和冠幅相容測試，共 16 項通過。

## 0.4 冠幅逐步量測

東西、南北向皆採準備 → 校正 → 近端第一點 → 遠端第二點 → 結果。兩點皆為樹冠垂直地面投影，非枝梢或樹影。第二點距離必須大於第一點；支援回退重測，兩次角度及距離會保存到 JSON 與 Excel 原始紀錄。碳存量與 Excel 計算公式未變。舊影片冠幅片段已加版本提醒。感測器精度仍需手機現場與捲尺比對；無法確認共線或等高時不適用此估測。

## 0.6.0 木材密度改用文獻值（2026-10-31）

- 木材密度不再統一採預設 0.60 g/cm³。計碳的 89 種全部填入 Global Wood Density Database（Chave 等 2009／Zanne 等 2009，doi:10.5061/dryad.234）的值：55 種為種階層平均，34 種查無該種、改用同屬平均，逐種以 `densityBasis` 標示「種」或「屬」。5 種學名已更新者對照 GWDD 舊組合取值（如 Camphora officinarum → Cinnamomum camphora）。棕櫚與竹類密度仍留空，不計碳。
- **碳存量數字因此改變，與 0.5.x 的輸出不可混用。** 例：樟樹周長 120 cm、樹高 12 m，0.5.x 為 330.0 kg C（密度 0.60），0.6.0 為 269.2 kg C（密度 0.487）。同一批調查請勿混用兩版匯出的 Excel。
- Excel 匯出的密度來源欄改標「文獻密度（種階層／屬階層）」，不再把查表值標為「實測密度」。密度欄有值即解除原計算表限制④（以預設密度估算者不得單獨對外引用）。
- 與原計算表逐值相符的回歸測試固定以預設密度 0.60 為基準，確保與 v1.2.1 計算表的對帳不受影響。23 項軟體測試通過（Node.js v26.13.0）。
- 屬階層取值的 34 種不確定性較高，榕樹等校園常見種在內；正式引用前建議替換為 Chao 等（2022）或林業試驗所資料庫的國內係數。

- 責任區選單新增「BQ · 棒球場」，排在最後，既有 13 個區碼不變。
- Excel 匯出同步更新：〈統計摘要〉第 36 列新增 BQ 株數；填寫表的「✗編號格式」檢核與「未歸區筆數」改為涵蓋 14 個區碼，BQ 開頭的樹木編號不會被判為格式錯誤。

## 0.6.5 選單更新即時生效（2026-11-09）

- 讀取責任區與樹種清單時一律向網站確認新版（no-cache，沒變時只回 304，幾乎不耗流量）。
- 加到主畫面的木測常被手機從記憶體恢復而不重新載入：切回 App 時（距上次檢查超過 1 分鐘）會自動重新檢查清單，有變動就更新選單並提示「已更新責任區」，保留目前已選的責任區與樹種，不影響填寫中的資料。


## 0.6.6 定位改為非必填（2026-11-14）

- **沒有座標也能保存與匯出。** 先前 `validateRecord` 強制要有 GPS，定位失效的手機完全無法交出資料；現在座標留空即可保存，Excel 的座標欄留白、備註欄標示「定位待補」。
- 新增手動輸入座標：定位區塊下方的「定位失敗怎麼辦？」可填緯度與經度並套用，備註欄標示「手填座標」。座標可在 Google 地圖長按該位置取得。
- 有填座標仍會檢查範圍（緯度 −90～90、經度 −180～180），避免把打錯的數字當成有效資料。
- 碳存量計算完全不受影響；沒有座標的紀錄一樣算得出碳值。
- 匯出的三處座標欄位（填寫表經緯度、量測原始紀錄的定位精度）皆改為可空白。
- 32 項測試通過，含「無座標可保存匯出」與「匯出標示待補且格子留白」兩項新測試。
